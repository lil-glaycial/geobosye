# 北京博士园官网

响应式品牌官网和可实际使用的内容管理后台。前台采用正式 Logo 的青绿色、白色与浅薄荷色，搭配清晰的中文无衬线字体和统一栅格；PC、平板、手机共用同一套响应式页面。

**部署与交接文档：[项目部署说明（含前后端）](docs/deployment.md)**。包含前后端架构、环境变量、Linux/systemd/Nginx、Docker、已有数据迁移、备份恢复、更新回滚与故障排查。

## 本地访问

- 官网：http://localhost:4173/
- 后台：http://localhost:4173/admin.html
- 本机登录凭据：项目根目录 `.local-credentials.txt`。首次登录或账号恢复后需要修改临时密码；改密后该文件不会自动更新。

已有业务数据的本机环境，确认依赖已安装后可重新启动：

```bash
cd /Users/peaklin/items/my/bjbsy
npm start
```

本机已配置 macOS 常驻服务，以免终端或工作会话结束后后台停止；同时监听 IPv4 与 IPv6 本地回环地址，`localhost` 与 `127.0.0.1` 都可访问，不对局域网开放。当前管理员为 `admin`，2026 年 10 月 21 日已恢复本机账号并生成新的临时密码，见 `.local-credentials.txt`；登录后按提示设置新密码。官网内容、图片及其他账号保留。

```bash
npm run start:local    # 启动本机常驻服务并验证可访问
npm run restart:local # 更新服务器代码后重启
npm run stop:local    # 停止本机服务
```

服务配置：`~/Library/LaunchAgents/com.bosye.website.local.plist`，登录 macOS 后自动启动；运行日志位于 `data/local-service/`。已运行常驻服务时，不要再次用 `npm start` 占用相同端口。其他操作系统仍使用 `npm start` 或相应进程管理器。

在新环境中安装（推荐 Node.js 22 LTS；当前版本也已在 Node.js 18.20.8 验证）：

```bash
npm ci
npm run setup
npm start
```

`setup` 只初始化空数据库，不覆盖已有管理员；默认账号 `admin`，密码随机生成并保存至仅当前用户可读的 `.local-credentials.txt`，首次登录强制修改。也可在初始化时通过 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 指定账号及至少 12 位密码。应用不会自动加载 `.env`，环境变量需由 shell、进程管理器或容器注入。

初始角色包括超级管理员、运营管理、内容编辑、只读查看。超级管理员角色不可编辑或删除；其他角色可调整。角色变更、停用账号、重置密码会撤销相关会话。普通角色不能授予超出自身范围的权限，也不能修改自己的角色权限。

前台咨询直接写入服务器 SQLite 数据库，后台数据不是 localStorage 模拟。没有接入短信、邮件、企业微信通知，管理员通过后台查看待跟进咨询。新增管理员由管理员设置初始密码并自行交付，不发送邮件邀请。

门店、服务、产品和文章的“展示图片”可点击打开图库，选择已有图片或上传本地图片。确认图片后返回原编辑表单，未保存的文案保留；点击表单“保存”后才更新该记录。取消选择保留原图，也可移除图片。媒体资源页支持独立上传与大图预览，上传权限由 `media.write` 控制，图库权限由 `media.read` 控制。

## 官网编辑

进入后台左侧“官网编辑”，页面按照官网从上到下的布局排列：顶部与首屏、首页模块、品牌资料与结构化模块、服务产品门店与资讯、资料详情页。客户在官网截图中标注的门店地址、伙伴姓名、品牌荣誉、服务弹窗、品牌资讯、资料中心和养护详情，都能从对应模块直接找到。

首页文字与图片、品牌使命、发展历程、科研数据、资质荣誉专利、服务参考价、合作店型、伙伴、培训和图库支持同页编辑、添加、删除与排序。服务、产品、门店、文章和品牌资讯也会按模块列出；点击“编辑”打开完整表单后，保存完成会返回“官网编辑”。微信公众号文章不会自动同步，需要在“品牌资讯”模块手动添加原文链接并发布。

资料详情页统一列出关于我们、联系咨询、FAQ、养护指南、对比、参考价格报告、隐私与条款等页面。默认内容随品牌知识库同步；修改后启用“使用自定义内容”，取消该选项可恢复默认内容。正文支持简单 Markdown：`## 标题`、`- 列表`、`**强调**`、`[文字](链接)`、`![说明](assets/图片.webp)` 和表格。保存会记录操作日志；查看使用 `site.read`，保存使用 `site.write`，选图与上传继续使用现有媒体权限。

- 六大服务与六大产品系列已有初始内容。门店明细、运营线索、文章均不编造，初始列表为空；门店资料录入并发布后可在官网搜索。品牌资料的“2000+”为品牌整体规模，与后台已录入门店数量口径不同。
- 合作案例为资料中的历史案例，不推断为当前经营业绩；页面保留参考说明。
- 官网、后台和页面图标使用旧官网正式 `logo.png`。公开页面图片来自旧官网与用户文档，主视觉为文档中的品牌门店设计资料，明确标注设计展示。旧站 8 个主要栏目、145 个可用关联资源和文档 8 张图片已归档；11 个旧站资源返回 404，清单见 `docs/content-sources.md`。
- 文档整理为 `content/knowledge.json`，原始文档与旧站页面保存至 `source-materials/`，不开放静态访问。公开页面展示精选内容与照片，原始历史海报保留归档。
- 产品、服务、门店、文章、品牌知识库、首页文案与图片、公开资料正文均可通过后台维护。初始知识库来自 `content/knowledge.json`，编辑内容保存在 SQLite 的 `settings.knowledge` 中。首页布局在源码中维护；`python3 scripts/build-home.py` 只重建基础模板，运行时仍优先使用后台保存的内容。本站不加载旧站归档的脚本或样式。
- 网站未加载第三方字体、广告或访问追踪脚本。

数据库位于 `data/bosye.sqlite`，媒体位于 `data/uploads/`。不要以静态目录服务器对外暴露整个项目，应通过 `npm start` 提供服务。服务器只开放明确列出的页面、静态素材及上传图片，数据库和账号文件没有公开路由。

## 部署

完整步骤见 [项目部署说明](docs/deployment.md)，配套提供 [systemd 服务模板](docs/bosye.service.example) 和 [Nginx 配置示例](docs/nginx.conf.example)。官网前端、后台页面与 API 共用一个 Node.js 服务，前端没有独立构建或启动步骤。

项目采用 Express + SQLite，适合单节点官网与管理后台；不包含多节点数据库复制、支付、短信、在线医疗或地图地理编码。

1. 在服务器安装 Node.js 22 LTS，运行 `npm ci --omit=dev`，设置持久化 `DATA_DIR`；仅空数据库初始化账号，迁移现有站点时恢复数据库和上传图片并跳过初始化。
2. 使用进程管理器运行 `NODE_ENV=production TRUST_PROXY=1 PUBLIC_ORIGIN=https://www.bosye.com HOST=127.0.0.1 PORT=4173 npm start`。实际发布域名不同时同步修改 `PUBLIC_ORIGIN`，该值仅填写协议与域名，不含路径。
3. 在前面配置单层可信 Nginx HTTPS 代理，参考 `docs/nginx.conf.example`。生产环境登录 Cookie 仅通过 HTTPS 发送。
4. 使用已核对的主体、备案、热线、门店明细和品牌授权图片。新上传内容的公开发布由后台发布开关控制。

也提供 `Dockerfile`，容器运行时将持久化目录挂载到 `/app/data`，端口只绑定服务器本地，再由 HTTPS 代理访问。首次需在容器内执行 `npm run setup`，使用 `docker cp` 取出 `.local-credentials.txt`。容器配置尚未在当前机器构建验证。

本次没有部署到公网，也没有修改旧官网。

## AI 信源检测

官网已按 `/Users/peaklin/items/agent/ai-agent-ready` 的 0.5.4 版原检测引擎调整。新增资料中心、独立品牌与联系页、FAQ、网站条款、养护选择清单、对比页、步骤指南和参考价格资料报告；产品与服务详情只根据后台已发布内容生成。页面提供自引用 Canonical、Open Graph、JSON-LD 与面包屑，公开内容按客户阅读需要呈现。

`/sitemap.xml` 与 `/llms.txt` 自动生成公开目录；后台、接口、数据库、上传目录和原始文档不列入站点地图。`/index.html` 与 `/privacy.html` 分别永久重定向到 `/` 与 `/privacy`。首页增加资料入口，主题延续品牌青绿色与柔和背景。

```bash
# 在本机的真实 HTTPS 连接下，使用原检测算法验证当前内容，非 100 分时失败退出
npm run audit:readiness
# 检查公开页面的桌面/手机布局、可访问性与无 JavaScript 阅读
npm run test:readiness-pages
# 公网发布后重新验证；公网请求使用检测项目的原安全抓取组件
node scripts/audit-readiness.mjs https://www.bosye.com/ test-results/ai-readiness-public.json
```

检测项目在其他路径时设置 `READINESS_EVALUATOR_DIR`。本地验证临时生成证书，并仅在验证子进程中信任它，不修改系统信任或关闭 TLS 校验；本地抓取适配仅允许目标回环主机和端口，发现与计分代码仍来自原项目。满分报告存于 `test-results/ai-readiness-after.json`，内容更新或部署配置变化后须重新验证。

生产环境推荐继续使用 Nginx 与正式域名证书，并将 HTTP 重定向到 HTTPS。也可通过 `TLS_CERT_FILE` 与 `TLS_KEY_FILE` 配置 Node 直接提供 HTTPS。`PUBLIC_ORIGIN`、代理协议、Canonical 与实际域名必须一致。本地 HTTPS 满分不等于旧域名已上线新版本；部署后的证书和域名仍需实测。

## 备份

```bash
npm run backup
# 或指定备份目的目录
npm run backup -- /absolute/path/to/backup-directory
```

使用 SQLite 在线备份 API 生成一致的数据库快照，并复制上传图片。备份包含咨询信息，应放在访问受限的位置。默认保存至 `data/backups/<时间>/`。

恢复时先停止应用，保存当前数据目录，再用备份中的 `bosye.sqlite` 和 `uploads/` 建立一个新的 `DATA_DIR`，然后启动；不要将旧 `-wal` 或 `-shm` 文件混入恢复后的目录。

### 品牌资讯

官网 `/news` 展示品牌资讯，每页 12 篇，按排序值升序、发布日期降序排列，详情地址为 `/news/:id`。后台选择「品牌资讯 → 添加品牌资讯」，填写标题、发布日期、摘要和正文，可选封面图片；勾选「发布到官网」后公开，未勾选则保存为草稿。正文支持 Markdown 标题、列表、加粗和本站图片。发布日期用于展示，不是定时发布开关。

品牌资讯沿用 `articles.read` / `articles.write` 文章管理权限，数据独立保存，不影响原有「内容发布」。公开详情会加入站点地图，草稿与删除的详情返回 404。

历史微信公众号文章清单保存在 `content/news-history.json`，由 `副本内容清单_合并.xlsx` 整理而来。需要在另一份数据库中恢复这批品牌资讯时运行 `npm run import:news`；脚本会先创建数据库备份，并使用固定编号避免重复导入。官网页面仅展示资讯标题与完整内容入口，账号、图片数量等编辑字段只供后台维护使用。

品牌资讯页面沿用首页植物、发丝与科研纹理，配置封面后会在列表显示图片。可手动运行 `node scripts/seed-news-demo.cjs` 添加 6 篇本地展示示例；脚本先备份数据库，重复运行不会覆盖或重复添加同一批示例，也不会随服务启动自动执行。示例可在后台品牌资讯中编辑、下架或删除。
